# 序言

## 为什么是 "The Hard Way"

QE 圈有个怪现象：**入门材料最多，入门的人最少。** 官方文档是参考手册式的，论坛答案散落在两千个帖子里，中文教程大多停留在"复制这个输入文件"的水平。于是大家都是"会跑 QE"，但问一句"`ecutwfc` 和 `ecutrho` 为什么差 4 倍（甚至 8/12 倍）"，一半人答不上来。

和姊妹篇一样的立场：**复制粘贴能出图，但不能让你知道自己出的是不是错的图。** QE 又恰恰是那种"错而不报"特别多软件——赝势不匹配能跑、k 网格不一致能跑、真空层不够也能跑，全等你论文返稿时一起算总账。

## QE 在你的工具链里站在哪

```
QE (pw.x)          ← 本书
   │
   ▼
Wannier90          ← Learn Wannier90 the Hard Way
   │
   ▼
WannierTools       ← Learn WannierTools the Hard Way
```

你如果是从姊妹篇倒着摸过来的，这本书会解答你在上游积累的所有"为什么"：为什么 NSCF 要用完整 k 网格？为什么 `nosym` ？为什么空带要给够？——答案都在 pw.x 的参数里。

## 心态：主动行动、思考

老三样，做不到劝退：

1. **别只看不练。** 每个输入文件自己敲。QE 的输入是自由格式 Fortran namelist，手敲一遍你就记住语法了。
2. **报错先自己读。** QE 的输出又臭又长，但错误一定在 `%%%%%%%%` 包着的段落里，Ctrl+F 十秒钟的事。
3. **多问为什么。** 每个参数写进输入文件之前问自己一句：默认值是什么？我为什么要改？

## 总结

- The Hard Way = 敲输入 + 读输出 + 问为什么；
- QE 是工具链最上游，上游的质量决定下游一切；
- "错而不报"是 QE 的常态，验收意识要自己带。
