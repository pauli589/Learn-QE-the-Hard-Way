# Ex1.2 安装与编译

**本节目标：** 集群上搞出能用的 `pw.x`。QE 编译比 WannierTools 友好得多，但坑在"环境组合"上。

## 1 获取

```bash
# 官网: https://www.quantum-espresso.org
# GitHub:
git clone https://gitlab.com/QEF/q-e.git q-e
cd q-e
git checkout qe-7.2        # 固定版本！记录 commit
```

!!! note "国内下载慢"

    老配方：`git clone https://gh-proxy.com/https://gitlab.com/QEF/q-e.git`

## 2 依赖

- **Fortran 编译器**：gfortran 或 ifort（MPI 包装器 `mpif90`）
- **MPI**：开放并行必装（IntelMPI/OpenMPI）
- **数学库**：MKL（Intel 全家桶）或 OpenBLAS + FFTW
- **可选**：ELPA（对角化加速）、Libxc（泛函）、HDF5

**最省事路线：Intel oneAPI 全家桶**（ifort + IntelMPI + MKL），QE 对它有原生优化。

## 3 编译三步

```bash
./configure                     # 自动探测环境
# 检查 make.inc 里的编译器/并行/数学库识别对不对
make pw                         # 只编 pw.x（第一次够用）
make pp                         # 后处理全家桶（dos.x/projwfc.x/pp.x/bands.x）
```

产物在 `bin/`。验证：

```bash
cd PW/examples/example01 && ./example01
# 或直接
echo "" | ../bin/pw.x           # 打印版本 banner 不崩即可
```

## 4 集群用户：先找 module

```bash
module avail qe 2>&1 | grep -i qe
module load q-e/7.2
which pw.x
```

有 module 直接用，**但要自查三件事**：版本号、是否并行编译（`mpirun -np 2 pw.x` 试一下）、后处理 `*.x` 是否齐全（很多集群只装了 pw.x）。缺什么回自己目录编一个，装到 `~/bin`。

## 5 常见编译报错

| 报错 | 药方 |
|---|---|
| `configure` 找不到 MPI | 先 `module load` 再 configure；或 `--with-mpi` 指路径 |
| FFT/BLAS 链接错 | make.inc 手写 MKL 链接行（Intel Link Advisor 生成） |
| `make pw` 中途某插件崩 | 加 `--disable-elses` 之类跳过非核心插件，别死磕 |
| gfortran 老版本语法错 | 换 ifort 或升级 gcc ≥ 9 |

## 6 本节总结

- clone → 固定版本 → configure → `make pw pp`；
- 集群优先 module，自查版本/并行/后处理三件事；
- 第一次只编 `pw` + `pp`，别全量 `make` 折腾自己。

## 师兄提醒

!!! warning "记录你的构建配方"

    复现类工作（姊妹篇的 WT 书反复强调）要求绑定版本：`git log -1 --format=%H` 的 commit、编译器/MPI/MKL 版本、configure 命令，全部写进 `~/qe-build-README.md`。**"我用的 QE 7.2"在三个月后等于什么都没说**，"commit xxxxxxx + oneAPI 2024.0"才是一条可复现的信息。
